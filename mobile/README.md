# Мобильный клиент AI Аренда

Обновлено 30.10.2026. Основной клиент использует тот же сервер, номер телефона, пароль и данные, что веб-сервис. Полная инструкция сборки и проверки — [MOBILE_RELEASE.md](../docs/MOBILE_RELEASE.md).

## Общий сервер

Задайте `EXPO_PUBLIC_API_URL` как корневой HTTPS-адрес работающего веб-сервиса. В режиме разработки по умолчанию используется `http://127.0.0.1:5174`; на физическом телефоне этот адрес указывает на сам телефон. Для испытаний на устройстве нужен доступный ему тестовый сервер. Сборка вне режима разработки отклоняет HTTP.

```sh
npm ci
npm run typecheck
npm start
```

Вход, регистрация и восстановление выполняются через `/api/mobile/auth/*`, бизнес-запросы — через общие `/api/*`. Мобильный токен хранится в Keychain/Keystore, привязан к адресу сервера и отделён от cookie браузера. Старые токены отдельного мобильного пилота автоматически не переносятся. Нельзя помещать ключ AI, банков или мессенджеров в переменные `EXPO_PUBLIC_*`.

Профиль и подключённые роли общие. Выход на одном устройстве не завершает остальные входы; управление сеансами находится в профиле. Восстановление пароля отзывает вход на всех устройствах. Резервный код показывается один раз и не сохраняется в переписке.

Веб-просмотр Expo на другом origin не получает автоматический CORS-доступ к общему серверу. Не ослабляйте проверку origin ради предпросмотра: используйте нативную сборку или развёртывание веб-клиента за согласованным общим origin.

## Проверки и сборки

```sh
npm test
npm run check:release
```

Тесты API создают временные базы. Проверка выпуска намеренно не проходит без рабочего HTTPS API, реквизитов оператора, поддержки, реального проекта Expo, подписанных артефактов и результатов испытаний устройств. Профили EAS подготовлены в `eas.json`; сборка и загрузка в магазины автоматически не выполняются.

Переходы `aiarenda://workspace/{role}/{section}?entity={id}` только открывают доступный процесс после входа и серверной проверки роли. Они не выполняют оплату, подтверждение, отправку сообщений или геолокацию. Ссылки из уведомлений используют ту же проверку. Доставка APNs/FCM требует отдельного подключения.

## Старый локальный адаптер

`npm run server` запускает прежний изолированный SQLite-адаптер на 8788 для регрессионных HTTP-тестов. Он сохраняет совместимость старых фикстур и поддерживает новый общий телефонный протокол на своей тестовой базе. Основной клиент больше не выбирает его по умолчанию. Его `mobile/data/rental.sqlite` не объединяется автоматически с базой веба: перенос реальных записей требует подтверждённого сопоставления владельцев аккаунтов.

Перенос всей новой карты и всех элементов веб-интерфейса в нативный клиент, физические испытания и подключение доставки отмечаются отдельно в приёмке. Наличие общих бизнес-правил и успешных тестов не подтверждает готовность к магазинам.
