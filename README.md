# AI Аренда

**Мобильное приложение Android / iOS:** исходники и отдельный сервер пилота в [`mobile/`](mobile/README.md). Интерфейс — одно окно разговора на React Native / Expo. Веб-версия ниже работает отдельно.

Рабочая первая веб-версия единого ассистента для гостей, владельцев и исполнителей уборки. Внешне — одно окно разговора без бокового меню, кабинетов и выбора роли. Ассистент определяет сценарий по обращению; сведения собираются вопросами, необходимые карточки и подтверждения появляются в переписке. React + TypeScript + Vinext; серверные маршруты Cloudflare Worker; постоянная база D1 (SQLite). Публикация Sites закрыта и доступна владельцу проекта.

## Что работает

- Вход через платформенную авторизацию ChatGPT; профиль с несколькими ролями.
- Каталог и добавление квартир. Точный адрес выдаётся подтверждённому гостю или назначенному исполнителю.
- Заявки на бронирование с резервом 30 минут, серверный расчёт по каждому начатому периоду 24 часа, подтверждение и отмена.
- SQL-триггеры запрещают пересечение броней с учётом времени уборки; истёкшие резервы перестают блокировать календарь даже без запущенного браузера.
- Автоматическое создание уборки после подтверждения брони с указанной стоимостью.
- Анкета исполнителя, открытые задания, отклики, назначение, начало работы, чек-лист, текстовый отчёт и приёмка.
- Ограничение пересекающихся назначений одному исполнителю на уровне базы.
- Диалоги, уведомления внутри приложения, журнал действий, обзор сохранённых показателей.
- Изолированные учебные объекты по кнопке «Попробовать на примере»; они не видны другим аккаунтам.

## Как проверить

1. Открыть сайт и написать «Покажи учебный пример». Если потребуется, войти через ChatGPT; незавершённая задача продолжится после входа.
2. Подтвердить добавление учебных данных и выбрать квартиру в переписке. Отправить заявку с будущими датами.
3. Написать «Мои квартиры», затем нажать «Заявки гостей». Подтвердить бронь и указать стоимость уборки.
4. Написать «Хочу работать на уборке» или «Найти уборку». Заполнить анкету, если её ещё нет, и откликнуться.
5. Написать «Мои квартиры» → «Уборки по квартирам», назначить исполнителя по отклику. Через «Мои задания» выполнить и отправить отчёт.
6. Для приёмки снова запросить уборки владельца. Начать уборку можно не раньше чем за час до задания.
7. Для проверки добавления объекта написать «Хочу сдать квартиру». Ассистент задаст вопросы по одному и покажет итог перед публикацией. «Стоп» останавливает незавершённый ввод.

## Разработка

Node >=22.13. Зависимости установлены по package-lock.json.

```powershell
node scripts/run-framework.mjs dev
node node_modules/typescript/bin/tsc --noEmit
node --test tests/service.test.mjs
node scripts/run-framework.mjs build
```

Локальный вход: `/signin-with-chatgpt?return_to=/`. Учебная идентичность включена только в portable dev; production её не содержит. Миграции применяются локально командой из README шаблона Sites; production применяет их при публикации. Не редактировать уже применённые миграции.

## Языковая модель

Адаптер `lib/ai.ts` использует серверный Responses API по официальной документации: https://developers.openai.com/api/docs/guides/text . Для включения нужны секрет `OPENAI_API_KEY` и переменная `OPENAI_MODEL`, заданные в настройках среды Sites, с новой публикацией. Не помещать ключ в исходники или клиентский код. Без ключа доступен сценарный ассистент.

Адаптер выключен в текущем интерфейсе: согласие на передачу в модель не отправляется. При подключении нужно добавить явное согласие пользователя. Телефоны и email маскируются как дополнительная мера, но это не полная анонимизация. Политика обработки и основания зарубежной передачи требуют проверки до реального запуска. В модель не передаются профили, адреса из базы и финансовые записи. Модель не имеет доступа к изменению броней и оплат. При ошибке или тайм-ауте работает сценарный ответ. Живой вызов модели без ключа не проверен.

## Границы этой версии

- Telegram, WhatsApp, банковские платежи, фото объектов и фотоотчёты не подключены. UI явно сообщает об этом. Реальные выплаты не выполняются.
- Проверка контакта по SMS, документов и квалификации исполнителя, договорное оформление найма, подписки SaaS и публичная модерация требуют следующих этапов.
- Автоподтверждение без участия владельца и синхронизация внешних площадок пока не включены.
- Встроенные уведомления создаются при событиях и запрашиваются фразой «Что нового». Фоновый планировщик напоминаний пока не настроен. Метод обслуживания `/api/maintenance` доступен авторизованному пользователю. Это не круглосуточный диспетчер с гарантированной доставкой во внешние каналы.
- На текущем хостинге не заявлена локализация данных в Казахстане. Для реального пилота с персональными данными требуется согласовать регион размещения и обработку данных, при необходимости перенести backend и базу на подходящую инфраструктуру.
- В закрытой публикации все роли можно проверить своим аккаунтом. Приглашение реальных пользователей и изменение аудитории — отдельный этап.
- Нужны эксплуатационные проверки резервного восстановления, мониторинг, ограничение нагрузки и юридическая подготовка перед коммерческим запуском. Отсутствие сбоев не гарантируется.

## Основные файлы

- `app/chat.tsx`, `app/chat.css`: единственное окно разговора и сценарии интерфейса.
- `app/api/[...path]/route.ts`: защищённые API.
- `lib/service.ts`: бизнес-процессы и права доступа.
- `lib/domain.ts`: валидация и сценарии.
- `db/schema.ts`, `drizzle/`: схема, индексы и ограничения.
- `tests/service.test.mjs`: интеграционные тесты реальной бизнес-логики на SQLite.
