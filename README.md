# AI Аренда

**Мобильное приложение Android / iOS:** исходники и отдельный сервер пилота в [`mobile/`](mobile/README.md). React Native / Expo с отдельными экранами ролей и ассистентом. Веб-версия ниже работает отдельно.

Веб-версия платформы с отдельными страницами гостя, владельца и исполнителя. Сначала вход и определение роли по профилю; затем — рабочие страницы и ассистент в контексте выбранной роли. React + TypeScript + Vinext; серверные маршруты Cloudflare Worker; постоянная база D1 (SQLite). [Страницы и правила доступа](docs/ROLE_PAGES.md).

## Что работает

- Вход через платформенную авторизацию ChatGPT; профиль с несколькими ролями, обязательный выбор активной роли и серверная защита её страниц/API.
- Каталог и добавление квартир. Каталог доступен после входа и выбора роли гостя. Точный адрес выдаётся подтверждённому гостю или назначенному исполнителю.
- Заявки на бронирование с резервом 30 минут, серверный расчёт по суткам, часам или ночам, подтверждение и отмена; снимок согласованных условий и депозита.
- SQL-триггеры запрещают пересечение броней с учётом времени уборки; истёкшие резервы перестают блокировать календарь даже без запущенного браузера.
- Автоматическое создание уборки после подтверждения брони с указанной стоимостью.
- Анкета исполнителя, открытые задания, отклики, назначение, начало работы, чек-лист, текстовый отчёт и приёмка.
- Ограничение пересекающихся назначений одному исполнителю на уровне базы. Фактическое заселение/выезд, отчёт и приёмка управляют готовностью квартиры; ремонт и блокировка не снимаются автоматически.
- Диалоги, уведомления внутри приложения, журнал действий, обзор сохранённых показателей.
- Изолированные учебные объекты по кнопке «Попробовать на примере»; они не видны другим аккаунтам.

## Как проверить

1. Открыть сайт, войти и выбрать роль. Для новой роли заполнить профиль.
2. Владелец: «Мои квартиры» → «Добавить квартиру»; затем тарифы/готовность, заявки гостей и уборки.
3. Гость: «Найти квартиру» → выбрать объект → расчёт → согласие с условиями → заявка. Статус — в «Мои брони».
4. Исполнитель: «Найти задания» → отклик. После назначения адрес и выполнение доступны в «Мои задания».
5. Владелец подтверждает фактический выезд, исполнитель отправляет отчёт, владелец принимает уборку.
6. Для другой роли нажать «Сменить роль». В разделе «Ассистент» можно попросить учебный пример; данные изолированы от других аккаунтов.

## Разработка

Быстрый запуск в Windows: дважды нажмите `start-local.cmd` в папке проекта. Затем откройте `http://127.0.0.1:5173/`. Окно сервера должно оставаться открытым; после его закрытия или перезапуска компьютера сервер нужно запустить снова. Повторный запуск проверяет порт и не поднимает второй сервер, если порт уже занят.

Node >=22.13. Зависимости установлены по package-lock.json.

```powershell
node scripts/run-framework.mjs dev
node node_modules/typescript/bin/tsc --noEmit
node --test tests/service.test.mjs
node scripts/run-framework.mjs build
```

Локальный вход: `/signin-with-chatgpt?return_to=/`. Учебная идентичность включена только в portable dev; production её не содержит. Миграции применяются локально командой из README шаблона Sites; production применяет их при публикации. Не редактировать уже применённые миграции.

## Языковая модель

Адаптер `lib/ai.ts` использует серверный Responses API по официальной документации: https://developers.openai.com/api/docs/guides/text . Для включения нужны секрет `OPENAI_API_KEY` и переменная `OPENAI_MODEL`, заданные в настройках среды Sites, с новой публикацией. Не помещать ключ в исходники или клиентский код. Без ключа доступен сценарный ассистент.

Адаптер выключен в текущем интерфейсе: согласие на передачу в модель не отправляется. При подключении нужно добавить явное согласие пользователя. Телефоны и email маскируются как дополнительная мера, но это не полная анонимизация. Политика обработки и основания зарубежной передачи требуют проверки до реального запуска. В модель не передаются профили, адреса из базы и финансовые записи. Модель не имеет доступа к изменению броней и оплат. При ошибке или тайм-ауте работает сценарный ответ. Живой вызов модели без ключа не проверен.

## Границы этой версии

- Telegram, WhatsApp, банковские платежи, фото объектов и фотоотчёты не подключены. UI явно сообщает об этом. Реальные выплаты не выполняются.
- Проверка контакта по SMS, документов и квалификации исполнителя, договорное оформление найма, подписки SaaS и публичная модерация требуют следующих этапов.
- Автоподтверждение возможно только после отдельного разрешения владельца для квартиры. Синхронизация внешних площадок пока не подключена.
- Встроенные уведомления создаются при событиях и запрашиваются фразой «Что нового». Фоновый планировщик напоминаний пока не настроен. Метод обслуживания `/api/maintenance` доступен авторизованному пользователю. Это не круглосуточный диспетчер с гарантированной доставкой во внешние каналы.
- На текущем хостинге не заявлена локализация данных в Казахстане. Для реального пилота с персональными данными требуется согласовать регион размещения и обработку данных, при необходимости перенести backend и базу на подходящую инфраструктуру.
- В закрытой публикации все роли можно проверить своим аккаунтом. Приглашение реальных пользователей и изменение аудитории — отдельный этап.
- Нужны эксплуатационные проверки резервного восстановления, мониторинг, ограничение нагрузки и юридическая подготовка перед коммерческим запуском. Отсутствие сбоев не гарантируется.

## Основные файлы

Исследование интерфейса, снимки до/после и единый план развития ИИ-администратора: [`docs/DESIGN_AUDIT_AND_ROADMAP.md`](docs/DESIGN_AUDIT_AND_ROADMAP.md). Первый этап реализован локально: публичный каталог без адресов и контактов, быстрые действия, серверный обзор задач, актуальные карточки и проверка стоимости/доступности перед заявкой. Второй этап добавляет почасовые/ночные тарифы, учёт депозита, полномочия владельца и фактические заселение/выезд/готовность. Платёжные операции и документы пока не подключены. [Авторизация и роли](docs/AUTHORIZATION_AND_ROLES.md): текущие ограничения и план единой учётной записи.

- `app/chat.tsx`, `app/chat.css`: единственное окно разговора и сценарии интерфейса.
- `app/api/[...path]/route.ts`: защищённые API.
- `lib/service.ts`: бизнес-процессы и права доступа.
- `lib/operations.ts`: обзор событий и задач каждого участника; `components/booking-request.tsx`: серверный расчёт и подтверждение заявки.
- `lib/domain.ts`: валидация и сценарии.
- `db/schema.ts`, `drizzle/`: схема, индексы и ограничения.
- `tests/service.test.mjs`: интеграционные тесты реальной бизнес-логики на SQLite.

## Инициативность ассистента

В разделе «Настройки» каждой роли доступны режимы «По запросу», «Важное», «Инициативный», заблаговременность и тихие часы. Ассистент предлагает задачи по текущим броням и уборкам при открытом приложении. Подробности, ограничения автономности и следующий порядок настройки: [docs/ASSISTANT_SETTINGS.md](docs/ASSISTANT_SETTINGS.md).

Для новой базы после `0001_rental_operations.sql` примените `0002_assistant_preferences.sql`. Мобильный сервер применяет обе дополнительные миграции при запуске. Круглосуточная доставка сообщений и выполнение действий языковой моделью пока не подключены.

## Календарь и аккаунт

Добавлены календарь каждой роли, согласование раннего заезда/продления/скидки, учёт доплаты и повторное согласие исполнителя после переноса уборки. Значок аккаунта открывает профиль и настройки оплаты; общий список пользователей доступен только серверному администратору. [Правила, состояние этапов и миграции](docs/OWNER_CALENDAR_ACCOUNT.md). Банковский API и рабочие инструменты облачной модели пока не подключены.

Навигация по референсу: боковая панель со значками на компьютере, нижняя панель основных разделов на телефоне и меню «Ещё» в шапке, аккаунт в нижнем углу. [Визуальная проверка](design-qa.md).


## Таймеры и согласования

После подтверждённого заселения и начала уборки отображаются таймеры: в карточке, обзоре и календаре на сегодня. Отсчёт восстанавливается по серверному времени; сдача отчёта останавливает работу, доработка сохраняет прежнее начало. В ассистенте доступны единые карточки брони, изменений условий, откликов, приёмки уборки и подтверждения выезда. Решение проверяется по роли, сроку и актуальной ревизии.

Перед запуском этой версии на существующей базе примените `drizzle/0005_activity_approvals.sql` после миграций `0000`–`0004`. Мобильный сервер применяет её при запуске. [Поведение, права и миграция](docs/TIMERS_APPROVALS.md).

## Карточки жилья и профили

Галерея до 8 фото, обложка, тип и площадь жилья, удобства, вместимость, тарифы, депозит, заезд и правила. Владельцу доступны формы создания, редактирования и публикации черновика. В аккаунте каждой роли — фото и форма профиля; у исполнителя также районы, опыт, график и приём заданий. Состояния квартир и исполнителей отражают рабочий процесс, а не имитацию присутствия в сети.

Перед запуском примените `drizzle/0006_listing_profiles.sql` после предыдущих миграций. Мобильный сервер применяет её при запуске. [Хранение фотографий, права, статусы и проверка](docs/LISTINGS_PROFILES.md).
