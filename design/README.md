# AI Аренда — Mobile & Web

Дизайн ориентирован на простую аренду на часы/сутки, единый аккаунт и дополнительные кабинеты. Существующий бренд сохраняет терракотовый акцент, светлые тёплые поверхности и Golos Text.

## Артефакты

- Figma: https://www.figma.com/design/e1uWm7axJ0ddYYlAEi1xfS
- Полный просмотр 71 экрана × 2 формата: `/design-review.html`.
- `figma/screens.mjs`: каталог страниц и сценариев. Только синтетические примеры.
- `preview-render.js`, `preview.css`, `preview.template.html`: воспроизводимый просмотр.
- `figma/foundations.js`, `figma/render.js`: исходники для Figma Plugin API / use_figma. Они исполняются в контексте Figma, не Node. Параметры renderer: MODE, GROUP, OFFSET, SPECS. ID текущих страниц: Mobile `5:932`, Desktop `5:933`; для другого файла нужно заново получить ID и перенести публичный логотип.

## Статус Figma

Бесплатный Starter позволяет три страницы; используются основа, Mobile и Desktop. В Figma сохранены 19 общих веб-макетов и первые 2 мобильных. Дальнейшая запись остановлена лимитом MCP. Не отмечать оставшиеся макеты как перенесённые. Часть созданных экранов ещё требует итоговой визуальной проверки в Figma после восстановления доступа.

Захват авторизованной страницы отклонён автоматической проверкой из-за персональных данных. В Figma загружен только публичный `public/brand-mark.png`. Личные данные и реальные объявления не передавались.

## Правила интерфейса

Телефон: 390 × 844, поля с постоянными подписями, цели нажатия 48–50 px, нижняя навигация, основное действие после условий. Веб: 1440 × 960, боковое меню, таблицы, дополнительная колонка для контекста. Содержимое длинных страниц прокручивается.

Бронирование: даты → точный расчёт → условия и отдельный депозит → согласие → заявка. Отправка не означает списание денег, подтверждение или завершённую оплату. По статусам ясно различаются черновик, проверка, активность и приостановка.

AI: помощь и подготовка действия, затем явное подтверждение существенной операции. Настройки разрешений отделены от переписки. Push включаются на устройстве самим пользователем. Секреты и внутренние идентификаторы не показываются в продуктовых сценариях.

Фотографии объявлений в макетах заменены оригинальными иллюстрациями интерьера. При внедрении используются фотографии проверенных объектов. Иллюстративная карта не содержит пользовательских координат.

## Источники решений

Использованы компоненты Material 3 Design Kit (кнопки) и Simple Design System (поля, карточки и навигация). Локальные брендовые переменные и типографика применены поверх структур библиотек. Apple UI kits и платные AI-функции не использовались.

Адаптивность: https://developer.android.com/develop/ui/compose/layouts/adaptive/use-window-size-classes
Доступность: https://www.w3.org/WAI/WCAG22/quickref/
Лимиты Figma: https://developers.figma.com/docs/figma-mcp-server/rate-limits-access/

## Внедрение

В текущем изменении опубликован просмотр дизайна. Рабочие страницы приложения автоматически не заменяются макетами. Для внедрения по очереди обновить оболочку и общие компоненты, сценарии гостя, владельца, исполнителя и админские разделы; после каждого этапа проверить реальные действия и роли. Не переносить демонстрационные суммы и статусы в production-данные.
