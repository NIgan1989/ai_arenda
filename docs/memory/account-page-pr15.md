2026-11-12 пользователь попросил улучшить страницу аккаунта и профиля («простая логика отображения, технологичные подходы»). Показаны 3 макета (1 «Список», 2 «Визитка», 3 «Две вкладки»), файлы в `/mnt/project-files/account-page/`. Рекомендован и сделан вариант 1: PR #15 https://github.com/NIgan1989/ai_arenda/pull/15, ветка claude/project-thread-7b648w. Пользователь сказал «сливай», PR слит 2026-11-12 (main a5edc81), публикация в Cloudflare прошла (run 43279714467). Затем пользователь заметил, что гостю с одной ролью не должны показываться чужие роли: на сайте переключатель и так показывает только подключённые роли; в приложении строка «Сменить роль» для аккаунта с одной ролью переименована в «Сдавать жильё или работать на уборках» (PR #16, слит 2026-11-12, main e45ea58).

Сайт: `components/account-control.tsx` + `components/account-list.css` (классы `acct-*`, намеренно новые имена, чтобы уйти от старых слоёв CSS `.account-control`/`.role-profile` в mobile-first.css и warm-theme.css, которые остались мёртвыми). Вложенные блоки (push, сеансы, «Мои данные», «Данные для AI») стали `details.acct-details` и используются также в operations-hub и platform-admin. Переключатели сохраняются сразу через `/api/account` и `/api/profile/edit` с откатом при ошибке.

Приложение: `mobile/src/AccountRows.tsx` (Group, Row, SwitchRow), `mobile/src/AccountControl.tsx`; иконок и SVG в приложении нет, поэтому вместо кольца полоса заполненности.

Не проверено: физический телефон; строка «Уведомления» во включённом состоянии (на стенде push не подключён). Идеи из отклонённых вариантов: кнопка «ИИ допишет профиль», цифры по роли (нет данных об оценках).

Стенд: вход для скриншотов через `fetch('/api/auth/login',{phone,password})` со страницы /signin; тестовый владелец qa-owner на стенде является администратором платформы. См. [[design-system]], [[palette-redesign-pr12]], [[chat-edge-pr13]].
