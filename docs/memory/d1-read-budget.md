# Лимит чтений D1 (2026-11-21)

Бесплатный тариф Cloudflare D1 разрешает 5 млн прочитанных строк в сутки. Лимит сбрасывается в 00:00 UTC (05:00 Алматы).
Когда он исчерпан, падают и миграции при публикации, и сам сайт.

Так случилось 2026-11-21. Публикации #193 и #195 упали на `d1 migrations apply`
с ошибкой «exceeded D1's free tier daily row read limit».

## Что читало больше всего
Замер на тестовой базе (900 объектов, примерно в 6 раз больше боевой). Это Miniflare D1: `meta.rows_read` совпадает с подсчётом Cloudflare.

- Обход «уборка не начата» (`lib/overdue-cleaning.ts`, `sweepLateStart`): 469 000 строк за один проход раз в 2 минуты.
  Для каждой назначенной уборки он читал весь журнал `audit_events`: на нём не было ни одного индекса.
- Проверка каждого владельца (`checkAdministratorOwner`) раз в минуту: около 6 700 строк.
  Таблицы `properties`, `cleaning_jobs` и `profiles` по владельцу и городу читались целиком.
  Советы (окна в календаре, прогноз недели, совет к объявлению, цена уборки) каждый раз читали весь город.
- Обновление экрана приложения раз в 15 секунд: 8–18 тыс. строк.
  `property_policies` и `property_operations` читались целиком, весь каталог приходил при каждом обновлении.

## Исправление
- Миграция `0085_read_indexes.sql`: индексы для горячих вопросов.
- Советы владельцу раз в час (`ADVICE_EVERY`, ключ `advice:<id>` в `administrator_runs`).
- Фоновая проверка владельца раз в 2 минуты (`OWNER_EVERY`). Действия человека и обновление приложения запускают её сразу.
- `state` читает правила и готовность только своих объектов.
- Приложение берёт каталог при фоновом обновлении раз в 5 минут (`CATALOG_EVERY`). Между этими обновлениями оно запрашивает `?catalog=0`, а на карте остаётся прежний список.

После исправления на той же базе:
- проход по опозданиям: 2 строки;
- проверка владельца: около 500;
- обновление приложения без каталога: около 2 500.

Тест: `tests/read-budget.test.mjs`. Он проверяет, что горячие вопросы идут по индексу.

Новый запрос в фоне или в `state` проверять так же: EXPLAIN QUERY PLAN не должен показывать `SCAN <таблица>` у большой таблицы.
К запуску с живыми пользователями нужен платный план Workers: 5 $ в месяц, 25 млрд строк.

## Публикация после лимита (2026-11-22)
Пока на сайте старый код, он снова съедает лимит за несколько часов после 00:00 UTC. 22 ноября его исчерпали уже к 05:35 UTC.
Поэтому публикация, запущенная днём, падает на миграциях.

`deploy.yml` теперь запускается и по расписанию, в 00:10 UTC (05:10 Алматы), сразу после обновления лимита.
Он публикует main, только если проверки main прошли.
