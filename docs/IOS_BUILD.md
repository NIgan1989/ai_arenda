# Приложение для iPhone: тестовая сборка

Обновлено 12 ноября 2026 года. Это сборка для пилота, а не для App Store.

## Главное

Apple не даёт поставить на iPhone приложение, которое не подписано сертификатом Apple. Поэтому GitHub собирает файл **без подписи**, а подпись добавляется одним из двух способов:

| Способ | Что нужно | Как долго работает приложение | Кому можно дать |
| --- | --- | --- | --- |
| Свой Apple ID, программа Sideloadly | Бесплатный Apple ID, компьютер с Windows или macOS, кабель | 7 дней, потом подписать заново | Только на свои устройства |
| TestFlight | Платный аккаунт Apple Developer Program (99 долларов в год) | 90 дней на сборку, обновления приходят сами | До 10 000 тестировщиков по ссылке |

Для проверки на своём телефоне хватает первого способа. Для пилота с настоящими гостями и владельцами нужен второй.

## Где скачать

Постоянная страница: <https://github.com/NIgan1989/ai_arenda/releases/tag/ios-latest>, файл `ai-arenda-unsigned.ipa`.

Прямая ссылка на файл: <https://github.com/NIgan1989/ai_arenda/releases/download/ios-latest/ai-arenda-unsigned.ipa>.

Страница появляется после первой успешной сборки в ветке `main`. Файл заменяется после каждого изменения приложения в `main`, так же как у [Android-сборки](ANDROID_BUILD.md). Сборки из pull request лежат во вкладке Actions, «Build iPhone test app», раздел Artifacts, архив `ai-arenda-ios` (30 дней).

## Установка своим Apple ID (бесплатно)

Один раз:

1. На компьютере с Windows поставьте iTunes и iCloud **с сайта Apple**, не из Microsoft Store (Sideloadly работает только с этими версиями).
2. Скачайте и поставьте Sideloadly: <https://sideloadly.io>.
3. На iPhone с iOS 16 или новее после первой установки включите «Настройки → Конфиденциальность и безопасность → Режим разработчика» и перезагрузите телефон.

Каждый раз:

1. Скачайте `ai-arenda-unsigned.ipa` по ссылке выше.
2. Подключите iPhone кабелем, на телефоне нажмите «Доверять этому компьютеру».
3. В Sideloadly перетащите файл в окно, впишите свой Apple ID и нажмите Start. Лучше завести отдельный Apple ID для тестов.
4. На iPhone откройте «Настройки → Основные → VPN и управление устройством», выберите свой Apple ID и нажмите «Доверять».
5. Войдите в приложение тем же номером телефона и паролем, что на сайте.

Ограничения бесплатного Apple ID: приложение перестаёт открываться через 7 дней (поставьте файл заново, вход сохранится), одновременно не больше 3 таких приложений на телефоне.

## TestFlight (когда появится аккаунт Apple Developer)

Что нужно от владельца проекта:

1. Оформить Apple Developer Program: <https://developer.apple.com/programs/enroll/>. Для компании нужен номер D-U-N-S, для физического лица хватает Apple ID с двухфакторной защитой. Одобрение занимает от одного до нескольких дней.
2. В App Store Connect создать приложение с идентификатором `app.aiarenda.assistant`.
3. Создать ключ App Store Connect API (роль App Manager) и передать его в настройки репозитория как секреты.

После этого в эту сборку добавляется шаг подписи и отправки в TestFlight, и каждая сборка из `main` будет приходить тестировщикам сама.

## Почему не Expo Go

Приложение сделано на Expo SDK 57. Expo Go из App Store открывает проекты только одной версии SDK, и на ноябрь 2026 года это не 57. Собрать Expo Go под нужную версию (`eas go`) можно только через тот же платный аккаунт Apple Developer. Кроме того, Expo Go требует, чтобы проект раздавал компьютер разработчика.

## Ограничения сборки

- Подпись. Файл без подписи, сам по себе на iPhone не ставится (см. выше).
- Проверка. Автоматически проверяется только то, что приложение собралось, у него правильный идентификатор и номер сборки, а внутри правильный адрес сервера. На iPhone сборку нужно проверять вручную; на 12.11.2026 таких проверок ещё не было.
- Сервер. Приложение работает с <https://ai-arenda.ai-arenda-kz.workers.dev>. Другой адрес задаётся переменной репозитория `ARENDA_PUBLIC_URL`.
- Значок. Своего значка пока нет. Чтобы добавить, укажите поле `icon` в `mobile/app.json`.
- Уведомления. Push-уведомления не подключены: для них тоже нужен аккаунт Apple Developer.

## Как устроено

Файл `.github/workflows/ios.yml`. Запускается при тех же изменениях, что Android-сборка (папки `mobile/`, `lib/`, файл `design/tokens.json`, проверка `scripts/check-mobile-release.mjs` и сам файл сборки), или вручную: Actions, «Build iPhone test app», «Run workflow» на ветке `main`. Репозиторий открытый, поэтому машины macOS на GitHub бесплатны.

Шаги:

1. `npm ci` в `mobile/` и проверка `app.json` и адреса сервера.
2. В `app.json` на сборочной машине номер сборки (`buildNumber`) приравнивается к номеру запуска. Версия остаётся `0.1.0`, потому что iOS принимает только числовую версию. В репозиторий ничего не записывается.
3. `npx expo prebuild --platform ios` создаёт папку `mobile/ios` и ставит CocoaPods.
4. `xcodebuild ... CODE_SIGNING_ALLOWED=NO` собирает приложение для настоящих iPhone (не для симулятора).
5. Папка `.app` упаковывается в `Payload/` и архив `ai-arenda-unsigned.ipa`.
6. Проверяются идентификатор, номер сборки и адрес сервера внутри приложения.
7. Сборки из `main` отдельное задание кладёт в предварительный релиз `ios-latest`. Только оно может изменять репозиторий.
