# Импорт собственных квартир

Владелец открывает «Управление → Импорт», скачивает CSV-шаблон, загружает CSV или JSON, выбирает подходящие строки и подтверждает создание **черновиков**. До подтверждения квартиры не создаются. Данные других аккаунтов и их совпадения не показываются.

Предел одной загрузки: 25 квартир, 280 КБ UTF-8. CSV поддерживает BOM, запятую или точку с запятой, экранированные кавычки и переносы строк внутри кавычек. Первая строка — имена полей. Поддерживаются английские имена из шаблона и русские: `название`, `город`, `район`, `адрес`, `описание`, `цена`, `комнаты`, `гости`, `уборкамин`, `внешнийid`, `фото`. Неизвестные/повторяющиеся столбцы и несовпадающее число полей отклоняются. Формулы не выполняются.

JSON — массив объектов или объект `{ "properties": [...] }`. Пример:

```json
[
  {
    "title": "Квартира у парка",
    "city": "Павлодар",
    "district": "Центр",
    "address": "Свой точный адрес",
    "description": "Своё описание квартиры",
    "price": 15000,
    "rooms": 1,
    "capacity": 2,
    "cleaningMinutes": 90,
    "externalId": "my-apartment-1"
  }
]
```

Цена — за сутки, в целых тенге. `externalId` необязателен, но полезен для повторных выгрузок. Он принимает строку до 150 символов без управляющих знаков или неотрицательное целое число в безопасном диапазоне JSON; для длинных числовых ID используйте строку. Источник (`manual`, `krisha`, `booking`, `airbnb`, `other`) — пользовательская отметка происхождения предоставленных материалов, а не подтверждение интеграции с площадкой.

Фото добавляются через существующую форму «Мои квартиры». JSON также может содержать `photos` — до восьми ID фотографий, ранее загруженных этим владельцем. Чужие ID и HTTP-ссылки отклоняются. Импорт не скачивает внешние страницы, файлы или картинки и не запрашивает пароль площадки.

Предпросмотр сохраняется на сервере на 15 минут с версией и хешем. Ошибочные и повторные строки не выбираются для импорта. Совпадения определяются **среди квартир текущего владельца** по городу/нормализованному адресу или источнику/внешнему ID; регистр, повторные пробелы, `е/ё` и простая пунктуация учитываются. Это консервативная защита от повторного добавления, а не геокодирование или установление права собственности. При спорном совпадении владелец редактирует имеющуюся карточку; импорт никогда не перезаписывает её автоматически.

При подтверждении сервер заново проверяет совпадения и принадлежность фото. Выбранные строки сохраняются одной транзакцией вместе с журналом и результатом импорта. Повтор подтверждения того же предпросмотра с теми же строками возвращает прежние ID, включая повтор после истечения срока. Другой набор строк с использованным предпросмотром отклоняется. Если данные изменились до фиксации, запрос отклоняется целиком: частично созданных квартир нет.

Созданные квартиры скрыты от гостей, имеют состояние «Требует проверки» и отключённые автоматические полномочия. Из файла не принимаются `ownerId`, `published`, готовность, статусы проверки или автоназначение. Площадь, тип жилья, правила, депозит, время заселения и фотографии не выдумываются: владелец заполняет их в форме перед публикацией. Применяются отдельные правила допуска платформы.

Сохранившиеся предпросмотры доступны в истории для продолжения после перезагрузки. Исходные материалы сохраняются в базе в форме нормализованных строк; это персональные данные владельца. Истёкшие неподтверждённые предпросмотры удаляются при подготовке следующего файла. Лимиты проверяются атомарно: до пяти новых предпросмотров за минуту и до 20 действующих неподтверждённых предпросмотров. Реестры выполненных импортов сохраняются для защиты от повторов.

API интеграции:

- `previewPropertyImport(service, { source, format, content })` — подготовка.
- `previewPropertyImport(service, { id })` — открыть сохранённый предпросмотр.
- `commitPropertyImport(service, { id, expectedVersion, payloadHash, rowNumbers, confirmed: true })` — зафиксировать выбранные строки.
- `importState(service)` — собственная история и лимиты.
