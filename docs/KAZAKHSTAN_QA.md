# Тестовая база Казахстана

Дата создания: 29 октября 2026. Только изолированный стенд **http://localhost:5174/**. Рабочая база http://127.0.0.1:5173/ не заполнялась тестовыми объявлениями.

90 городов, по 10 опубликованных вымышленных объявлений: **900 объявлений**. На город — 2 владельца, 3 гостя, 3 исполнителя: **720 новых аккаунтов** (180/270/270). Три исходных технических аккаунта стенда сохранены, их небольшое исходное объявление убрано из публичного каталога. Оператор платформы — исходный qa-owner, серверное право действует только на тестовом стенде.

Контроль числа городов и областного распределения: https://stat.gov.kz/ru/industries/social-tatistics/demography/publications/335821/ (на 1 июля 2026). Справочник имён: tests/fixtures/kazakhstan-cities.json. Источник наименований указан в нём отдельно. Это тестовые объекты во всех городах, а не выгрузка реальных объявлений.

Все имена, адреса, цены и номера для входа синтетические. Фото — технические заглушки. SMS, Telegram/WhatsApp, платежи и объектное хранилище отключены конфигурацией TEST_DATA_ONLY. По явному разрешению пользователя включены реальные ответы OpenAI с существующим серверным ключом. Для этого launcher сохраняет локальное согласие в outputs/browser-qa/ai-settings.json; в каждом чате остаётся кнопка согласия «Включить OpenAI». Вызовы расходуют баланс API. Фоновый процесс запускается вместе с тестовым сервером. Проверки владения и телефона не выдаются за реально проведённые. Общий известный пароль предназначен только для этих синтетических аккаунтов; стенд нельзя публиковать с этими данными входа.

## Входы для совместной проверки в Павлодаре

Общий тестовый пароль: `Kazakhstan-fixture-2026`.

| Роль | Номер для входа |
| --- | --- |
| Владелец №1, пять квартир | +70000000529 |
| Гость №1, заявка ожидает решения | +70000000531 |
| Гость №2, частичная оплата | +70000000532 |
| Гость №3, бронь с назначенной уборкой | +70000000533 |
| Исполнитель №1, назначенная уборка | +70000000534 |

Оператор платформы: `+77000000001`, пароль `Browser-fixture-2026` (исходный технический аккаунт).

Полная таблица всех городов: outputs/browser-qa/kazakhstan/accounts.csv. Отдельные JSON-файлы содержат аккаунты, объявления и сценарии. Согласованная копия базы — test-database.sqlite в той же папке.

## Что проверять

1. В поиске выбрать город: без фильтра дат база содержит ровно 10 объявлений. На конкретные даты часть скрывается из-за брони или ремонта — это ожидаемо.
2. Войти гостем №1: открыть заявку. В другом профиле браузера войти владельцем №1 и подтвердить либо отклонить её. Изменения проверить в обоих кабинетах.
3. Гость №2 и владелец №1: проверить остаток частичной оплаты и отдельный депозит. Любые отметки переводов здесь — учебные, деньги не переводятся.
4. Гость №3 / владелец №1 / исполнитель №1: проверить согласованную бронь и уборку. Для этого сценария часы брони сдвинуты в текущий учебный интервал: заселение и выезд не отмечены, оплаты не придуманы. После проверки тестовых оплат и депозита владелец может подтвердить заселение, затем гость сообщает о выезде, владелец проверяет освобождение. Исполнитель начинает работу, прикладывает JPEG до/после и сдаёт отчёт, владелец принимает.
5. Проверить ремонт квартиры №5, невозможность чужого доступа, разные роли и обращение по проблеме.

Брони и задания созданы с реальными временными ограничениями. Срок заявки истекает через 30 минут, начальные сценарии со временем устаревают. Повторный запуск генератора не сбрасывает уже проведённые пользователем проверки. Для позднего повторного теста можно создать новую бронь на свободном объекте.

## Воспроизведение и результат

`node scripts/start-browser-qa.mjs` — запуск изолированного стенда. Для совершенно нового стенда сначала запросить /api/public/catalog, затем выполнить `node scripts/seed-browser-qa.mjs --confirm-isolated`. Расширение: `node scripts/seed-kazakhstan-qa.mjs --confirm-isolated`. Повтор не создаёт дубли. Скрипты отказываются работать с .wrangler рабочей базы или с не-QA аккаунтами.

Проверка: `node scripts/check-kazakhstan-qa.mjs`. Пройдены 93 проверки: 90 каталогов городов и 3 набора проверок входа/ролей/приватности. На данном локальном запуске среднее время запроса 150 мс, максимальное 443 мс; это последовательная проверка, а не испытание параллельной промышленной нагрузки. Отчёт check-report.json находится рядом с базой.

Найдена и исправлена ошибка: точный запрос «Шар» раньше включал Шардару и Ушарал. Теперь известный полный город совпадает точно, а неполные названия продолжают поддерживаться. Добавлен регрессионный тест. 59 тестов существующей бизнес-логики, 2 новых проверки, TypeScript и сборка прошли.
