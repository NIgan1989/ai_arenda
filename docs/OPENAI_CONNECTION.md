# OpenAI в веб-чате

В локальном проекте сервер читает `.dev.vars` в корне. Нужны `OPENAI_API_KEY` и `OPENAI_MODEL`. Файл исключён из Git. Не добавляйте ключ в JavaScript браузера, исходники или переписку.

Текущая настроенная модель: `gpt-6-luna`. Ключ и доступ к модели проверены; короткий реальный запрос через API самого приложения вернул `mode: model` и ответ. Изменения `.dev.vars` подхватывает локальный сервер; после первого создания файла может понадобиться перезапуск `start-local.cmd`.

AI администратор работает по серверной конфигурации без пользовательского переключателя. Поле aiConsent игнорируется обоими HTTP-адаптерами. Окно открывается через логотип или контакт администратора в чатах. Открытие истории не вызывает модель.

При отправке запроса в OpenAI передаются сообщение, до восьми предыдущих реплик этой роли и краткий снимок данных: город, названия, публичные тарифы/правила, даты, суммы и статусы доступных броней и заданий. У каждого списка максимум 15 записей. Профильные имена, контакты, точные адреса, фото, коды доступа и данные других ролей исключены из снимка. В сообщениях маскируются телефоны, email и строки, похожие на API-ключи; это не полная анонимизация произвольного текста. Запрос использует `store:false`; это не обещание отсутствия любых технических журналов у провайдера.

Переписка сохраняется в локальной базе по аккаунту и роли и восстанавливается при открытии диалога администратора. Пользовательское название — «AI администратор», без технических подписей поставщика. Ошибки баланса, ключа, модели, сети и частоты запросов имеют явный сценарный fallback.

Ограничения: 30 запросов в час на аккаунт суммарно по ролям, 200 запросов в час на весь сервис, один вызов модели на сообщение, максимум 1400 выходных токенов. Это ограничения количества запросов, не денежный лимит. Для production нужны отдельный контроль расходов и настройки биллинга OpenAI.

Модель пока отвечает и объясняет текущие данные; у неё нет инструментов изменения броней, оплат, тарифов и назначений. Такие действия подтверждаются в формах и проходят существующие серверные проверки. Контроль цепочек, постоянные задачи и фоновые напоминания реализует отдельный серверный [AI администратор](AI_ADMINISTRATOR.md). Он работает при запущенном сервере. Банковские события и внешние уведомления не подключены. Нативный мобильный пилот сохраняет сценарный режим.

Локальные секреты подгружаются через автоматически созданный `.sites-local.wrangler.json`; он тоже исключён из Git и используется только в режиме dev. Production-сборка не копирует локальные секреты; при размещении их надо задать в секретах хостинга.
