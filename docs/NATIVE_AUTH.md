# Вход без ChatGPT

Веб-приложение использует собственные аккаунты: имя, номер телефона и пароль от 10 символов. Аккаунты хранятся в D1/SQLite. Вход через ChatGPT и его заголовки больше не предоставляют доступ к пользовательским данным. Существующие записи старых аккаунтов не переносятся на новый номер автоматически: совпадение контакта не подтверждает владение аккаунтом.

При регистрации один раз показывается случайный резервный код. Его нужно сохранить. «Забыли пароль?» принимает номер, резервный код и новый пароль; заменяет код и завершает все старые сессии. Без пароля и резервного кода самостоятельное восстановление невозможно. SMS, email и внешние сервисы не требуются. Номера нормализуются, но не подтверждаются: это идентификатор для входа, а не доказательство владения номером. Не используйте его как признак проверенного владельца жилья.

Перед запуском обновлённой веб-версии примените `drizzle/0007_native_auth.sql` после предыдущих миграций. Локальная команда (из корня, с актуальным Node.js):

```
node scripts/setup-native-auth.mjs
```

Пароли: PBKDF2-SHA512, 100 000 итераций (лимит Web Crypto в Workerd), случайная соль. Случайные сессии и резервные коды хранятся только как SHA-256 хеши. Сессия живёт 30 дней, cookie HttpOnly/SameSite=Lax, Secure на HTTPS. Смена пароля отзывает сессии по версии учётных данных. Запросы авторизации требуют совпадающий Origin и JSON; ограничения попыток хранятся в базе отдельно по номеру и IP. В production используется доверенный CF-Connecting-IP, локально общий лимит. Лимиты хеширования и CPU необходимо проверить на выбранном тарифе перед размещением; локальная проверка не подтверждает работу на облачном тарифе.

Новая авторизация относится к веб-приложению. Мобильный сервер сохраняет существующую независимую авторизацию. Данные прежнего локального ChatGPT-профиля остаются в базе, но не присваиваются новым аккаунтам.
