# Общие компоненты интерфейса

Применено 29 октября 2026 по исследованию [RECOMMENDATION.md](design-research/RECOMMENDATION.md).

## Что используется в продукте

- `app/design-system.css`: единые цвета, отступы, размеры полей и кнопок, состояния, мобильные размеры. shadcn/ui на существующих Radix Primitives; 219 кнопок и полей в 25 продуктовых файлах переведены на общие компоненты. Число файлов не означает визуальную проверку каждого состояния всех страниц.
- `CatalogPage`: React Hook Form + Zod, город, гости, вид аренды, диапазон дат (DayPicker), цена, комнаты, сортировка. Дополнительные параметры раскрываются отдельно. Сервер возвращает максимум 60 объектов, интерфейс запрашивает по 24. Сначала проверяется доступность и стоимость на весь период, потом применяются ценовые фильтры и пагинация. Адрес и контакты в публичную проекцию не добавлены.
- `RecordCollection`: TanStack Table 9, сортировка, поиск, вкладки состояний, 12 записей на странице, карточки для телефона и таблица владельца, детали в Radix Sheet. Действия существующих карточек сохранены. Личный статус отклика исполнителя учитывается отдельно от общего статуса задания.
- `RentalCalendar`: стандартные представления FullCalendar 7 (неделя, месяц, повестка), русский язык, Asia/Almaty, фильтр объекта владельца. Старое представление сохранено как запасное при ошибке компонента. Перетаскивание дат отключено: изменение условий требует существующего согласования. Просроченный срок сам по себе не подтверждает выезд.
- `WorkspaceProvider`: QueryClient на экземпляр приложения, ключи включают аккаунт и активную роль. Каталог и состояние кабинета имеют отдельные ключи. Изменения сбрасывают соответствующие данные; операции изменения не повторяются автоматически. Входящие сообщения и счётчик навигации используют общий запрос с интервалом 8 секунд; фоновые опросы скрытой вкладки отключены. Чтение открытого диалога пока использует отдельный опрос 4 секунды, сохраняющий порядок страниц истории.
- `PropertyGallery`: Embla для жестов/перелистывания, просмотр через Yet Another React Lightbox с увеличением и скачиванием. При открытии проверяются права через существующий API, данные приватных фото не сохраняются в постоянном хранилище браузера.
- `AvatarPicker`: react-easy-crop для перемещения, жестов и масштаба; результат уменьшается до JPEG 512×512 и существующего лимита размера. Фото чата открывается внутри родительского диалога, чтобы не терять фокус и верхний слой.
- Чаты на широком экране: список и переписка рядом. На узком экране используется полноэкранный диалог. Владелец общается с гостем и назначенным исполнителем в разных приватных комнатах. Сообщения и фото не включаются в контекст модели.
- Управление: подключения, расчёты, участники и контроль сгруппированы через Radix Tabs с сохранением доступных функций каждой роли.

## Проверка

`node scripts/verify-local.mjs`: схема, TypeScript, 154 бизнес-теста, 35 HTTP-тестов, production-сборка прошли. Лог: `outputs/design-verification.log`. Новые проверки: пагинация/цены/сортировка и безопасная проекция каталога, сокращённое состояние кабинета, статусы откликов, события календаря без уборок у гостя и без автоматического подтверждения выезда.

В браузере проверены загрузка каталога, таблица владельца, сортировка и открытие деталей, переход из карточки в приватное обсуждение, двухколоночная переписка, недельный/месячный календарь и адаптивная навигация. Снимки: `outputs/design-chats-desktop.png`, `outputs/design-catalog-mobile.png`. Это выборочная проверка основных семейств экранов, а не полный аудит доступности или всех 25 маршрутов.

## Границы этого этапа

- Общие поля уже используются в существующих формах. Полностью на RHF + Zod переведена форма поиска; остальные формы сохраняют свою проверенную отправку и серверную валидацию. Перенос остальных форм возможен отдельно по мере изменения их сценариев.
- Общие токены имеют приоритет над старыми таблицами стилей; старые стили не удалены массово. Разделены каталог, календарь и общие списки, но центральный контроллер кабинета остаётся в `app/chat.tsx`.
- Серверный каталог пока строит разрешённую публичную проекцию перед фильтрацией; SQL-пагинация с индексами — отдельная оптимизация при росте объёма.
- Storybook и платные ресурсные представления календаря не подключены. Деплой и новые внешние интеграции в этот этап не входят.
