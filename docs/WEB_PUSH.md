# Уведомления браузера

В профиле каждого кабинета есть «Уведомления на устройстве». Включение только по нажатию пользователя. Для iPhone/iPad: iOS 16.4 или новее, добавить сайт на экран «Домой», открыть установленный сайт и включить уведомления. [Документация WebKit](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/).

Настройка сервера: один постоянный комплект `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (реальный HTTPS-адрес сервиса), плюс `ACCESS_ENCRYPTION_KEY`. Создание ключей: `node scripts/setup-web-push.mjs`. Скрипт добавляет отсутствующий комплект в игнорируемый `.dev.vars`, не выводит значения. Переносить на сервер через защищённые secrets. При смене ключей устройства должны повторно включить подписку. Отдельного платного SMS/Apple Developer аккаунта для Web Push не требуется.

Очередь D1 получает новые уведомления только после включения подписки, отдельно по пользователю и роли. Планировщик Cloudflare обрабатывает очередь каждую минуту. Есть аренда задания, повтор временных ошибок, ограничение числа попыток, тихие часы и удаление подписки при ответе 404/410. Принятие провайдером означает отправку, а не подтверждение показа или прочтения.

Endpoint и ключи устройства зашифрованы в базе. Допускаются только HTTPS-адреса известных браузерных push-провайдеров, без переадресаций. На экране блокировки общий текст без адресов, содержимого переписки, платежей и кодов замков. Ссылка ведёт только в свой кабинет, где доступ снова проверяет сервер.

Подписка связана с текущим веб-сеансом: выход, отзыв сеанса и восстановление пароля удаляют её каскадно. Уже принятый провайдером пакет отозвать невозможно. Отключение в одном кабинете не затрагивает другие роли на том же устройстве. Уведомления зависят от разрешений браузера, настроек ОС, интернета и режима фокусирования. Проверка доставки запускается отдельной кнопкой пользователя, не чаще раза в минуту.

Service Worker не кеширует страницы или API. Он отображает уведомления и открывает приложение. Эта реализация относится к веб-сайту/PWA. Нативные Expo push требуют отдельной сборки приложения, настройки проекта и проверки на физических устройствах.
