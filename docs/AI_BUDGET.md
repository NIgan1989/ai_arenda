# Учёт и ограничения AI

Новые таблицы `0014_ai_budget.sql` хранят настройки аккаунта и резерв каждого обращения. Одна настройка действует для всех ролей аккаунта. Общие ограничения платформы задаются только сервером.

Перед `fetch` Responses API сервер сохраняет резерв **одним условным SQL INSERT**, проверяющим одновременно дневные лимиты аккаунта и платформы. Параллельные запросы разных аккаунтов не могут каждый использовать один и тот же остаток. Тот же `requestKey` не разрешает повторную отправку. При нехватке бюджета модель не вызывается; формы и фоновые правила остаются доступны.

День учёта — Казахстан, UTC+5. По умолчанию: аккаунт до 200 обращений/500000 токенов в день; платформа до 1000 обращений/3000000 токенов. Существующий часовой ограничитель запросов продолжает действовать отдельно. Пользователь может приостановить модель и установить меньшие ограничения. Обновление настроек проверяет версию. Из тела запроса нельзя выбрать чужой аккаунт.

## Денежная оценка

Стоимость не считается нулевой при отсутствии тарифов. Для локальной денежной оценки нужны **все три** серверные настройки:

```text
AI_PRICE_MODEL=<точное значение OPENAI_MODEL>
AI_INPUT_USD_PER_MILLION=<положительное число USD за миллион входных токенов>
AI_OUTPUT_USD_PER_MILLION=<положительное число USD за миллион выходных токенов>
```

Тарифы задаёт администратор после проверки актуальной цены своего проекта/модели; код не содержит выдуманной цены по умолчанию и не меняет модель. Включённый денежный лимит при отсутствующих/несовпадающих тарифах блокирует вызов модели.

Общие лимиты сервера:

```text
AI_GLOBAL_DAILY_REQUEST_LIMIT=1000
AI_GLOBAL_DAILY_TOKEN_LIMIT=3000000
AI_GLOBAL_DAILY_USD_CAP=
```

Пустой денежный лимит отключает только денежное ограничение. При включении денежного ограничения неизвестная стоимость уже состоявшихся обращений текущего дня препятствует новым вызовам до начала нового учётного дня. Тарифы сохраняются в резерве; последующее изменение серверной цены не переписывает старые записи.

Вход резервируется консервативной оценкой размера полного JSON-запроса, включая инструкции, историю и схему инструмента, плюс запас протокола; выход — максимум 1400 токенов. После успешного ответа с корректным `usage` резерв заменяется сообщённым API числом входных и выходных токенов. [OpenAI Docs](https://developers.openai.com/api/docs/guides/token-counting) уточняет, что выходные токены включают невидимые служебные/рассуждающие токены, поэтому видимый размер ответа не используется для расчёта.

При timeout, сетевом сбое, ответе 5xx или отсутствующем `usage` результат считается неподтверждённым: резерв сохраняется. При явном отклонении 400/401/403/404/422/429 токены и сумма резерва освобождаются; попытка остаётся в количестве запросов. Завершение одного резерва повторно не изменяет его сумму.

Это **локальный защитный учёт по заданным тарифам**, а не выписка/жёсткий платёжный лимит OpenAI: он не видит другие приложения проекта, изменения тарифов, фактические скидки и биллинг провайдера. Сверка с OpenAI и проектные ограничения расходов настраиваются отдельно. Неизвестный результат не трактуется как бесплатный.

## Защита поручений

Модель не выполняет операции напрямую. Перед передачей серверному обработчику проверяются вид инструмента, одна функция за ответ, допустимые поля, текущая роль и принадлежность идентификатора снимку роли. Уборка требует даты, начала/окончания, цены и описания; дата/время и стоимость должны присутствовать в пользовательских репликах, чтобы модель не подставляла их сама. Неоднозначный запрос возвращает уточнение. Текстовое сообщение модели не заменяет карточку/подтверждение и не может заявить выполнение запрошенной операции.

Проверки `tests/ai-scenarios.test.mjs` покрывают недостаток данных, выдуманные условия, чужой объект, неизвестный/множественный инструмент, лишние поля, сломанный JSON, инструкции из контекста и ложный текст об исполнении. Даты ISO с часовым поясом и UUID сохраняются при удалении контактов/ключей из текста. Окончательную проверку прав, сроков, тарифов и версий перед фактической операцией выполняют доменные методы.

## Подключение

`generateAnswer(...,toolExecutor,createAIBudgetLifecycle(db,userId,config,requestKey))` — сохраняет резерв непосредственно перед сетью, затем учитывает результат до подготовки поручения. `aiBudgetState` возвращает собственные показатели и последние 30 обращений; глобальные показатели возвращаются только при `platformAdmin=true`. Сами тексты сообщений в журнал бюджета не записываются.
